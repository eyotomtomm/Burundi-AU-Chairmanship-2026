Flutter app 2.0.0+57 · 170 Dart files · 60 screens Django 4.2 backend · custom admin portal · DigitalOcean App Platform Branch home-rail-and-media-perf
Not ready to ship

The foundations are better than average: fail-secure settings, signed private media, a deny-by-default admin permission model, and a Flutter client that starts fast and caches well. But the release path itself is broken (the backend cannot build on its pinned Python, CI never runs), the admin portal has no working second factor, one scheduled task deletes paused users' accounts, and six live app-to-API calls point at endpoints that do not match. Twelve blockers are listed below in the order to fix them.

Twelve ship blockers

Each of these was verified against the source, not just reported. Numbers are priority order.

  1. Rotate every credential in the recovery doc, then delete it. A plaintext file on disk holds the live Django secret key, the managed Postgres password, the Gmail app password, the Twilio auth token and the full Firebase service-account key. It is gitignored and was never committed, but it sits in a synced Downloads folder.
    burundi_au_chairmanship/DIGITALOCEAN_RECOVERY.md:15,25,46,56,83
  2. Stop the daily task that hard-deletes "Take a Break" accounts. Deactivation sets is_deactivated; the beat task deletes every such user after 30 days while the email promises "your data is safe". Filter on is_scheduled_for_deletion instead.
    core/tasks.py:104-116 · core/views.py:586-603 · config/settings.py:635
  3. Make admin login actually require TOTP, and fix the forced password change. Templates for 2FA exist, django-otp is installed, but no view checks it. The forced-change flag is only checked at login (any later URL works) and the change page itself 403s for non-superusers, so invited admins cannot change their temp password.
    custom_admin/views.py:221-263 · custom_admin/permissions.py:137-142
  4. Put the auth decorators on the notification-create view. They were applied to its validation helper instead. Anonymous GET renders the admin push form; the POST is blocked only by accident.
    custom_admin/views.py:1097-1101
  5. Make admin_sections read-only in the profile serializer. Any authenticated user can PATCH their own profile and grant themselves every admin section.
    core/serializers.py:66-76, 157-181 · core/views.py:566-573
  6. Unblock the backend build. runtime.txt pins Python 3.9.18 but Pillow 12.1.0 requires Python 3.10+, so a fresh DigitalOcean build fails at pip install. Django 4.2 left extended support in April 2026. Move to Python 3.12 and Django 5.2 LTS, and align the Dockerfile and CI, which currently use 3.11.
    backend/runtime.txt · backend/requirements.txt:4,9
  7. Make CI run. The workflow lives at burundi_au_chairmanship/.github/workflows/; GitHub only reads the repo root. Once moved it still fails: Flutter is pinned to 3.32 but the pubspec needs 3.38, and the Firebase config files plus key.properties are gitignored and never restored from secrets.
    burundi_au_chairmanship/.github/workflows/ci.yml:15,124-134 · .gitignore:39-46
  8. Fix six live app-to-API mismatches. Event file upload builds /apievent-submissions/upload-file/ (missing slash). Session revoke POSTs to a DELETE-only route. Notification preferences POSTs to a GET/PUT route. Live Q&A upvote uses a path that does not exist. The verification request drops the picked ID document. The Continental Dialogue apply form drops its file fields.
    lib/services/api_service.dart:1051,1620,1656,1715,1190 · youth_dialogue_apply_screen.dart:405-434
  9. Ship or remove four dead app features. Resources View/Download only show snackbars. Support ticket cards have no tap handler, so the list cannot open a ticket. Bookmarks has a screen and API but nothing routes to it and nothing calls add. Social Media shows fabricated follower counts when the API fails.
    resources_screen.dart:341-371 · support_tickets_screen.dart:313-364 · bookmarks_screen.dart · social_media_screen.dart:24-79
  10. Store readiness. Android App Links list only the upload key fingerprint, so Play-signed builds fail verification and share links open in the browser. Five permissions (fine/coarse location, contacts, read/write calendar) have no code behind them. Release builds are not obfuscated. iOS notification extension is hardcoded to version 1.0, which App Store Connect rejects.
    backend/config/urls.py:45-49 · AndroidManifest.xml:14-22 · ios/Runner.xcodeproj/project.pbxproj:632-668
  11. Wire the schedulers and close the registration race. Nothing flips scheduled content to published and nothing promotes the event waitlist; both commands exist but are not in the beat schedule. Scheduling a one-time notification from admin 500s on a naive datetime. Event capacity is checked with exists/count/save and no lock, and rejected submissions count against capacity forever.
    core/management/commands/publish_scheduled.py · custom_admin/views.py:1119,1165 · core/views.py:3810-3827
  12. Fix client-IP handling and login lockout. The Cloudflare middleware only trusts CF-Connecting-IP when the peer is a Cloudflare range, but on App Platform the peer is DigitalOcean's router, so every request shares one IP. Auth throttles then lock out everyone behind a point of presence together. The JWT login also bypasses django-axes by calling check_password directly.

Done well

Backend

  • Settings fail loudly on missing secret key or allowed hosts; HSTS with preload, secure cookies, proxy SSL header, PII off in Sentry.
  • SimpleJWT with 15 min access, 7 day refresh, rotation and blacklist; password change revokes all tokens.
  • OTP codes hashed at rest, five-attempt lockout, pending signups live only in cache until verified.
  • Private media (support, verification, YD documents) on a separate private-ACL storage with signed v4 URLs and no CDN domain, covered by a test.
  • Object-level scoping correct for tickets, bookmarks, conversations, reminders, submissions, sessions, comments.
  • Counters via F(), like state via Exists, WebP conversion and thumbnails off the read path, push in 500-token batches with stale-token cleanup.
  • Migrations run once in a PRE_DEPLOY job; Celery beat runs on one instance; gunicorn sized honestly for the plan.

App and admin

  • Startup is non-blocking: Firebase gated at 5 s, splash capped at 6 s with partial data, messaging and remote config deferred.
  • In-flight GET deduplication, bounded retries honouring Retry-After, maintenance detection via header and body.
  • Optimistic like store with debounce and honest revert; heartbeat and socket services pause in background.
  • Hive cache tiers with cache-first home, magazine and events tabs; tabs keep scroll state.
  • ARB files at exact parity (202 keys each) with a bridge that lets remaining strings migrate without call-site churn.
  • Deep links centralised with ID validation; cold-start links held until Home exists.
  • Admin: every POST form has a CSRF token, user content autoescaped, CSV formula-injection sanitised, Axes lockout, superuser-only admin management with self-lockout guards.
  • Signing hygiene: keystore, key.properties, .p8, .env, service-account JSON all untracked and never committed.

Method: five parallel read-only code audits (backend security, backend correctness and performance, Flutter app, admin portal, platform and deployment) plus Django deploy check, Django and Flutter test suites, flutter analyze, and a test-client render of all 55 admin pages against a database copy. Every critical finding was re-verified against source before inclusion. No files were modified.
